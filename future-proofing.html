What This Page Is

How the website is hosted and set up, how a release goes out, and what to check when something goes wrong. Nothing links here, it isn't in the sitemap, and search engines are asked to leave it out, but the site's repo is public, so anyone could find it there: it never holds passwords, keys, or tokens, or how the site guards against attacks (those are only in the private API repo's notes). It loads no scripts, so it opens even when the rest of the site has trouble. Everything the site does is in How Prismal Budget Works.

Last checked: October 27, 2026 (site version 10.27.2026.B).

2. Sending Out A Release

  1. Work on the Testing branch.
  2. Change the version everywhere it's written: SITE_VERSION in Javascript/Boot.js (today's date and the next letter, like 10.27.2026.A, then .B), How It Works' "Last updated" line and its dateModified, and sitemap.xml's lastmod for the public pages that changed.
  3. Only when the Privacy Policy & Terms of Use change: its policy-version and policy-changes tags and both Effective Date lines, set to the day it goes live. A new policy-version emails every account with a verified email, once it's live.
  4. Run node _tools/stamp.mjs, which writes every file's fingerprint (section 3). The repo's pre-commit hook (turned on with git config core.hooksPath _tools/hooks) refuses a commit whose fingerprints are out of date.
  5. When the API changed (or the site calls something new on it), it goes first: in the API's folder, npx wrangler secret list (every secret still set), the tests (npx vitest run), then npx wrangler deploy. Running it from the wrong folder deploys nothing new.
  6. Commit on Testing, merge it into main (git merge --no-ff Testing), and push both. GitHub Pages publishes within a minute.
  7. Check that the live /Javascript/Boot.js says the new SITE_VERSION (pages show it at the bottom corner too).

3. Caching (Why Updates Show Up At Once)

  • Every page, and Javascript/Boot.js, are sent with Cache-Control: no-cache and aren't kept at Cloudflare's edge, so browsers ask for a new copy each time (it's quick when nothing changed).
  • Every other file (scripts, stylesheets, images, fonts, sounds) is loaded at an address ending in ?v= and its fingerprint: the first 10 hex digits of the SHA-256 of its contents (line endings don't count). Those addresses are kept for 30 days, at Cloudflare's edge and in browsers. A changed file gets a new address, so an old copy is never used.
  • Pages list their files' fingerprints in their links, and Boot.js lists the scripts' (FILE_VERSIONS). _tools/stamp.mjs writes them all.
  • A change that doesn't show up: check the live Boot.js's version, then whether the file's fingerprint was stamped before the commit. Purging Cloudflare's cache (Caching, Configuration, Purge Everything) is always safe.

4. Cloudflare's Settings

  • DNS: prismalbudget.org and www point at GitHub Pages, proxied (GitHub's custom domain help lists its addresses). www and plain http:// are sent on to https://prismalbudget.org by GitHub (the 301 comes from GitHub, so Cloudflare's Always Use HTTPS stays off).
  • Configuration Rule "GitHub DNS renewal": for the path /.well-known/acme-challenge/, SSL is off, so GitHub Pages can renew its HTTPS certificate for the custom domain. Without it, the certificate stops renewing, and GitHub's Pages settings show a certificate problem.
  • Cache Rules: addresses with ?v= are cached 30 days (edge and browser); pages (paths ending in .html or in nothing) and /Javascript/Boot.js aren't stored at the edge.
  • Transform Rules (response headers): Cache-Control: no-cache for pages and Boot.js, and "Security Headers" (section 5).
  • Minimum TLS version: 1.2.
  • Before turning on a Cloudflare feature that adds its own script to pages (some security and bot features do), check the private API repo's notes: a script the Content-Security-Policy (section 5) doesn't allow is refused, and pages can break.
  • On: Email Address Obfuscation, which rewrites email addresses in pages as they're sent. A page with an address in it (How It Works, the Privacy Policy, Settings, Spreadsheets) never matches its file byte for byte, and that's expected.
  • Web Analytics: Cloudflare adds its script (static.cloudflareinsights.com) to pages sent to browsers (not to tools like curl).
  • API tokens made for scripts expire. When a script says it isn't allowed, make a new one in Cloudflare (My Profile, API Tokens) with only what that script needs.

5. Headers Every Response Has

Anyone can see these (they come with every page), so they're written out in full. The Content-Security-Policy is Cloudflare's "Security Headers" Transform Rule.

Content-Security-Policy: default-src 'self'; script-src 'self' https://*.googletagmanager.com https://static.cloudflareinsights.com https://challenges.cloudflare.com; frame-src https://challenges.cloudflare.com; connect-src 'self' https://*.google-analytics.com https://*.analytics.google.com https://*.googletagmanager.com https://www.google.com https://prismal-budget-api.prismalbudget.workers.dev/; img-src 'self' data: https://*.google-analytics.com https://*.googletagmanager.com; style-src 'self'; font-src 'self'; worker-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
X-Frame-Options: DENY
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Cross-Origin-Opener-Policy: same-origin
Permissions-Policy: geolocation=(), camera=(), microphone=(), usb=(), bluetooth=()
X-XSS-Protection: 0
  • What each host in the policy is for: googletagmanager.com loads Google Analytics, and its hits go to google-analytics.com, analytics.google.com, and www.google.com; static.cloudflareinsights.com is Cloudflare Web Analytics; challenges.cloudflare.com is Turnstile (a script and a frame); the workers.dev address is the API.
  • What the site needs from it: img-src data: (stylesheet.css carries the background image inside it, so it shows with the first frame), worker-src 'self' (the starfield runs in a worker), connect-src 'self' (Boot.js fetches the star image early), and style-src 'self' (so every style has to be in a stylesheet: no style attributes or <style> tags).
  • Adding an outside service: add its address to the matching part of the policy first, or browsers refuse it. The console says "Refused to load ... because it violates the following Content Security Policy directive".
  • Strict-Transport-Security with includeSubDomains and preload: browsers only use HTTPS for the domain and every subdomain, for two years. Any new subdomain needs HTTPS working from the start.

7. The API

  • Deploying: npx wrangler deploy from the API's folder (the saved wrangler sign-in is enough). npx wrangler deployments list shows each version, and npx wrangler rollback goes back to the one before. npx wrangler tail shows its logs as they happen.
  • Secrets: set with npx wrangler secret put and its name; npx wrangler secret list shows which are set. Which ones there are, and what each one is for, is in the private API repo's notes. Without them, sign-in, emails, spreadsheets, reminders, or Create Account's person check stop working, each with a message saying so.
  • The database: every part of a budget is one row of JSON per person, up to about 1.9 MB each (D1 keeps up to 2 MB in one value; a bigger save is refused with "That's more than one part of a budget can hold."). People can keep their own copy with Download My Data, and bring one back with Upload A Backup (both in Settings). D1's Time Travel can put the whole database back to an earlier minute (npx wrangler d1 time-travel; how far back depends on the plan).
  • Testing on this computer: npx wrangler dev --local serves it at http://127.0.0.1:8787, and the site uses that address when it's opened at localhost or 127.0.0.1 (Boot.js).
  • Privacy Policy update emails: every few minutes the Worker reads the live Privacy Policy page's policy-version tag; when it's new, every account with a verified email gets one email (a few each run) with the page's policy-changes text.

8. When Something Goes Wrong

What happensWhat to check
A change doesn't show upThe live Boot.js's version; GitHub's Pages settings and the repo's Actions tab (the publish can fail); the fingerprints (section 3); then purge Cloudflare's cache.
A page is blank, or something broke after a releaseThe browser's console. "Refused to ..." is the Content-Security-Policy (section 5). A script error: git revert the merge on main and push, then fix it on Testing.
The browser says the connection isn't privateGitHub's Pages settings (Custom domain should pass its check, with Enforce HTTPS on) and the "GitHub DNS renewal" Configuration Rule (section 4).
Nobody can sign in, or "Passwords aren't set up on the server yet"The Worker's secrets (npx wrangler secret list), then npx wrangler tail while trying.
Account emails don't arriveResend's dashboard (the domain still verified, the email sent), the DNS records (section 6), the spam folder, and the DMARC reports at admin@.
Spreadsheets shared with admin@ stop being readThe admin@ Google account's access the Worker holds may need making again; spreadsheets shared by link still work meanwhile.
Create Account's person check always failsCloudflare's Turnstile dashboard: the site key in Login.js and the Worker's secret have to be the same pair.
The API doesn't answernpx wrangler tail, the Workers dashboard in Cloudflare, and Cloudflare's status page.
Analytics stopped countingThe analytics hosts in the Content-Security-Policy (section 5); Cloudflare Web Analytics only counts browsers that load its script.
Phones keep showing an old page saved to the home screenPages are never cached (section 3), so pulling down to reload, or closing the app from the home screen and opening it again, gets the new one.

9. Files That Matter Most

  • Javascript/Boot.js: every page's first script. The version, each page's name from its address, which pages work without signing in, the API's address, and every script's fingerprint.
  • Javascript/Layout.js: what every page shares (sliding between pages, the footer, Help, signing out, the Quick Entry icon's app).
  • _tools/stamp.mjs and _tools/hooks/pre-commit: fingerprints, and the check before each commit.
  • CNAME, robots.txt, sitemap.xml, llms.txt, and 404.html (GitHub Pages shows it for any address it doesn't have).
  • how-it-works.html: the full guide to what the site does.
  • This page, future-proofing.html: update it when any of these settings change.
